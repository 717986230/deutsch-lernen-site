# 英语谐音重建（原型，**尚未应用到数据**）

## 已确证的问题

`data/en_categories.json` 的 7192 条英语谐音是**按字母机械音译**的，不是按发音，
会教错读音。证据：

| 抽查 | 结果 |
|---|---|
| 常见词人工核对 | 14/14 全错（ability 拼成「布伊尔伊特伊」，实际读 [əˈbɪləti]）|
| `-tion` 结尾 | 280/287 条拼成「什恩」（action → 诶克什恩，应为「诶克申」）|
| `-ble` 结尾 | 106/108 条拼成「布尔」|
| `-ity` 结尾 | 82/91 条拼成「伊特伊」|

对照：德语谐音是人工写的，质量良好（Guten Morgen → 古腾 摩根），
全库 0 处不一致。**问题只在英语。**

## 本目录的原型

`en_pinyin.py`：用 CMU 发音词典（ARPABET 音标，12.6 万词，覆盖本项目 98% 的单词条目）
按「声母+韵母」切音节，映射到汉字。已实现鼻韵尾归并（accent → 厄克森特，
而非机械的「厄克塞恩特」）。

**当前准确率：对 20 个常见词的人工参考，完全一致 13/20。**

已知未解决的缺陷：
1. **音节切分**：两元音间的单辅音应作下一音节声母（money = mo-ney），
   现仍会切成 mon-ey，输出「门伊」而非「马尼」
2. **R 卷舌化**：元音后的 R 应并入前字，现会单独成字（morning → 莫瑞宁，应为「莫宁」）
3. **AE 映射**：/æ/ 统一映射到「诶」，但 happy 更接近「哈皮」

## 为什么没有直接跑

13/20 的准确率不足以覆盖 7192 条线上数据——修好一批的同时会引入另一批新错，
净效果无法保证。**在准确率提上去并经人工抽检前，不应批量应用。**

## 建议的推进方式

1. 先修上面三个缺陷，把常见词准确率提到 ≥18/20
2. 用高频词表（如最常用 500 词）做人工抽检，逐条确认
3. 分批替换：先只替换四类确定错误的词缀（478 条），验证线上反馈
4. 再推进到全量

跑法：
```bash
pip install cmudict
python3 -c "
import sys; sys.path.insert(0,'tools')
import cmudict; from en_pinyin import word_to_hanzi
print(word_to_hanzi('ability', cmudict.dict()))"
```
